# AI SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rendere Ceremly citabile dai motori AI (ChatGPT, Perplexity, Google AI Overviews) e leggibile dagli agenti: file machine-readable, schema FAQ/SoftwareApplication, pagine comparison oneste, guida RSVP potenziata, log di monitoraggio.

**Architecture:** Route Nitro generano `/pricing.md` e `/llms.txt` da `shared/constants/pricing.ts` e runtime config (mai desincronizzati). Le pagine comparison sono una route dinamica `app/pages/compare/[slug].vue` guidata da `shared/constants/comparisons.ts` (slugs/meta) + copy in i18n, con prerender e sitemap generati dallo stesso modulo. Schema via `useSchemaOrg` (modulo `@nuxtjs/seo` già attivo).

**Tech Stack:** Nuxt 4, Nitro server routes, `@nuxtjs/seo` (nuxt-schema-org, sitemap), `@nuxtjs/i18n` (it default / en, strategy `prefix_except_default`), Vitest.

**Spec:** `docs/superpowers/specs/2026-07-11-ai-seo-design.md`. Deviazione approvata in pianificazione: URL comparison `/compare/[slug]` e `/alternatives/paperless-post` (path inglesi, convenzione del sito — non esistono customRoutes i18n; la spec usava `/confronta` come esempio).

## Global Constraints

- **Gotcha i18n '@'**: MAI un carattere `@` letterale nei valori dei file locale (`i18n/locales/*.json`) — rompe l'intero file in SSR. Se serve, usare la sintassi literal `{'@'}`. Evitare anche `{parola}` nei testi (è interpolazione vue-i18n): nei template di messaggio usare parentesi quadre `[nome]`, `[link]`.
- **Lingua**: copy prodotto/UI in italiano (it-IT.json) + inglese (en-US.json), SEMPRE entrambe le locale nello stesso task. Commenti codice, nomi test e log in inglese.
- **Branding env-driven nel codice**: `useRuntimeConfig().public.appName` / `public.baseURL` — mai hardcodare "Ceremly" o l'URL nel codice TS/Vue. "Ceremly" nei valori i18n e nei contenuti blog è ammesso (convenzione esistente).
- **SEO on-page**: `seoTitle` ≤ 60 caratteri, `seoDescription` ≤ 155 caratteri (finding audit SEO §3.4).
- **Onestà** (bonifica 2026-06-17): nessun numero inventato, nessun testimonial fittizio. Ogni claim sui competitor deve essere verificato sul loro sito nel task stesso; se non verificabile, la riga si OMETTE (non si inventa). Riconoscere i punti di forza dei competitor.
- **FAQ visibili**: lo schema FAQPage deve rispecchiare FAQ effettivamente renderizzate in pagina, mai schema-only.
- **Import da shared nel server**: `~~/shared/constants/...` (alias esistente, vedi `server/utils/creem.ts:13`).
- **Stile codice**: indentazione 4 spazi nei `.ts`/`.vue` (convenzione repo), single quotes nel codice app.
- **Commit**: uno per task, `--no-verify` non necessario. Push sempre manuale (mai push automatico).
- **Verifica build**: il gotcha '@' si manifesta solo in build — `pnpm build` è parte della verifica finale, non opzionale.

import {
    CEREMLY_TIER_LIMITS,
    CELEBRATION_PRICE_CENTS,
    ATELIER_PRICE_CENTS,
    isUnlimited,
} from "~~/shared/constants/pricing";

function guests(tier: keyof typeof CEREMLY_TIER_LIMITS): string {
    const n = CEREMLY_TIER_LIMITS[tier].maxGuestsPerEvent;
    return isUnlimited(n) ? "Illimitati" : `fino a ${n} ospiti per evento`;
}

export function generatePricingMarkdown(opts: { appName: string; baseUrl: string }): string {
    const { appName, baseUrl } = opts;
    const celebrationEur = CELEBRATION_PRICE_CENTS / 100;
    const atelierEur = ATELIER_PRICE_CENTS / 100;

    return `# Prezzi — ${appName}

> Inviti digitali e RSVP per eventi privati (matrimoni, lauree, battesimi, compleanni).
> Pagamento una tantum per evento: nessun costo per ospite, nessuna percentuale sugli RSVP.
> Pagina prezzi: ${baseUrl}/pricing (English: ${baseUrl}/en/pricing)

## Free
- Prezzo: 0€
- Limiti: ${CEREMLY_TIER_LIMITS.free.maxGuestsPerEvent} ospiti per evento, ${CEREMLY_TIER_LIMITS.free.maxActiveEvents} evento attivo
- Include: 3 modelli di invito, RSVP via link personalizzato, dashboard risposte in tempo reale
- Nessuna carta di credito richiesta

## Celebrazione
- Prezzo: ${celebrationEur}€ una tantum per evento (non è un abbonamento)
- Limiti: ${guests("celebration")}
- Include: tutti i modelli e colori brand, inviti personalizzati WhatsApp ed email,
  domande RSVP condizionali (menu, allergie, accompagnatori), promemoria automatici,
  export lista per il catering
- L'upgrade da Free conserva invito, lista ospiti e risposte già raccolte

## Atelier (per event/wedding planner)
- Prezzo: ${atelierEur}€/mese (abbonamento mensile, disdici quando vuoi)
- Limiti: eventi illimitati, ospiti per evento: ${guests("atelier")}
- Include: workspace con il proprio logo, account team, API e integrazioni, supporto prioritario

## Note commerciali
- Evento consultabile per 12 mesi dopo la data (lista, risposte ed export inclusi)
- Rimborso completo entro 30 giorni se gli inviti non sono ancora stati inviati
- Fattura elettronica per ogni acquisto
- Server in UE, GDPR compliant
- Gli ospiti rispondono senza account e senza app

Ultimo aggiornamento: generato automaticamente dal pricing corrente.

// shared/constants/comparisons.ts
// Comparison pages registry (AI SEO). Slugs drive: the /compare/[slug] page,
// prerender routeRules and sitemap entries in nuxt.config.ts, and the
// i18n key namespace ceremly.site.compare.<slug>.
export interface ComparisonMeta {
    /** URL slug: /compare/<slug> */
    slug: string;
    /** Competitor display name */
    competitor: string;
    /** Competitor homepage (source of the verified claims) */
    website: string;
    /** ISO date of the last claims verification against the competitor site */
    verifiedAt: string;
}

    { slug: "joinme", competitor: "JoinMe", website: "<URL verificato allo Step 1>", verifiedAt: "2026-07-11" },
];

export const COMPARISON_SLUGS = COMPARISONS.map(c => c.slug);

interface Faq { q: string, a: string }
// FAQ is optional per usecase: planner has none. tm() returns [] for missing keys.
const faqItems = (() => {
    const items = tm(`${base.value}.faq`)
    return Array.isArray(items) ? (items as Faq[]).map(x => ({ q: rt(x.q), a: rt(x.a) })) : []
})()
const faq = computed(() => faqItems)

// AI SEO: FAQPage schema mirrors the visible FAQ (only when the usecase has one).
if (faqItems.length) {
    useSchemaOrg([
        defineWebPage({ '@type': 'FAQPage' }),
        ...faqItems.map(x => defineQuestion({ name: x.q, acceptedAnswer: x.a })),
    ])
}
