# Creem Payments Code Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute the multi-agent Creem payments code review defined in `docs/superpowers/specs/2026-07-11-creem-code-review-design.md`, produce a verified findings report, and hand off a TDD fix plan for the selected findings.

**Architecture:** Two-stage. Stage A (this plan): inline scout → one Workflow run (5 parallel lens reviewers → code dedup → adversarial verify with 3 votes for P0/P1) → findings report committed to `docs/reviews/` → user gate on fix selection. Stage B (generated by Task 5, not pre-written here because fixes depend on findings that don't exist yet): a second plan `docs/superpowers/plans/2026-07-11-creem-fixes.md` with one TDD task per selected fix.

**Tech Stack:** Claude Code Workflow tool (multi-agent orchestration), Vitest (fix stage), git on branch `dev`.

## Global Constraints

- Branch: `dev`. Auto-commit ok, **push always manual** (project convention).
- Report file: `docs/reviews/CODE-REVIEW-CREEM-2026-07-11.md` (exact path from spec).
- Severity scale: P0 blocker (money loss / security breach), P1 real bug high impact, P2 should-fix, P3 minor.
- No unverified P0/P1 may appear in the report's confirmed section (3-vote adversarial verify, majority).
- Uncertain findings go to a "manual verification" report section and never into the fix plan.
- Fix plan scope: all P0, all P1, P2 only if high-impact/low-cost (user gate decides).
- No Creem dashboard access: provider-side config (webhook registration, product setup, live keys) becomes "manual operational verification" items, never code findings.
- Docs/comments in English (project language convention).
- No code fixes during Stage A — review only.

const VERDICT_SCHEMA = {
  type: 'object',
  required: ['verdict', 'reasoning'],
  properties: {

const CONTEXT = args.context

const BASE = `You are a senior code reviewer examining the Creem payment integration of a Nuxt 4 multi-tenant SaaS (Vercel serverless, Neon Postgres via Drizzle, Better Auth organizations, Creem via @creem_io/better-auth plugin).

${CONTEXT}

Read ALL perimeter files with the Read tool (absolute paths = repo root + relative path). Follow imports when needed to understand behavior. Review ONLY through your assigned lens. Report findings with exact repo-relative file paths and 1-indexed line numbers. Severity: P0 blocker (money loss / security breach), P1 real bug high impact, P2 should-fix, P3 minor. Only report real, code-evidenced issues — no style nits, no speculation, no duplicates of the "do not re-report" items in the context. If your lens finds nothing, verdict "clean" with empty findings.

YOUR LENS: `

const LENSES = [

phase('Find')
const reviews = (await parallel(LENSES.map(l => () =>
  agent(l.prompt, { label: `find:${l.key}`, phase: 'Find', schema: FINDINGS_SCHEMA })
))).filter(Boolean)

// Barrier justified: dedup needs ALL lenses' findings at once (spec phase 3).
const merged = new Map()
for (const r of reviews) {
  for (const f of r.findings) {
    const key = `${f.file}#${Math.floor(f.line / 15)}`
    const prev = merged.get(key)
    if (prev) {
      prev.lenses.push(r.lens)
      const order = { P0: 0, P1: 1, P2: 2, P3: 3 }
      if (order[f.severity] < order[prev.severity]) prev.severity = f.severity
      prev.duplicates.push({ title: f.title, lens: r.lens, description: f.description })
    } else {
      merged.set(key, { ...f, lenses: [r.lens], duplicates: [] })
    }
  }
}
const deduped = [...merged.values()]
const rawCount = reviews.reduce((n, r) => n + r.findings.length, 0)
log(`${deduped.length} unique findings from ${rawCount} raw`)

phase('Verify')
const ANGLE_TEXT = {
  correctness: 'CORRECTNESS: is the claimed behavior actually what the code does? Read the exact files and lines cited. Check the claim against the real control flow, not the finding\'s paraphrase.',
  exploitability: 'EXPLOITABILITY / REPRODUCIBILITY: can the failure scenario actually happen given auth middleware, validation, plugin config, and callers? Trace the full request path from route (or webhook entry) to repository.',
  impact: 'IMPACT: is the severity justified? What is the real blast radius (money lost? cross-tenant mutation? audit gap only?). Downgrade or upgrade severity with evidence.',
}
const verifyPrompt = (f, angle) => `You are an adversarial skeptic. A code review of the Creem payment integration produced the finding below. Your job is to try to REFUTE it with code evidence.

${CONTEXT}

FINDING:
${JSON.stringify(f, null, 2)}

YOUR ANGLE — ${ANGLE_TEXT[angle]}

Read the actual files with the Read tool. Verdict "confirmed" ONLY if the finding survives your attack; "refuted" if the code already handles it or the scenario is impossible; "uncertain" if code alone cannot decide (e.g. depends on Creem dashboard config or undocumented @creem_io/better-auth plugin internals you cannot read — check node_modules/@creem_io/better-auth first before declaring plugin behavior unknowable).`

const verified = await parallel(deduped.map(f => () => {
  const highSev = f.severity === 'P0' || f.severity === 'P1'
  const angles = highSev ? ['correctness', 'exploitability', 'impact'] : ['correctness']
  return parallel(angles.map(a => () =>
    agent(verifyPrompt(f, a), { label: `verify:${f.file}:${f.line}`, phase: 'Verify', schema: VERDICT_SCHEMA })
  )).then(votes => {
    const vs = votes.filter(Boolean)
    const nConf = vs.filter(v => v.verdict === 'confirmed').length
    const nRef = vs.filter(v => v.verdict === 'refuted').length
    let status
    if (highSev) status = nConf >= 2 ? 'confirmed' : (nRef >= 2 ? 'refuted' : 'uncertain')
    else status = vs[0] ? vs[0].verdict : 'uncertain'
    const adj = vs.filter(v => v.verdict === 'confirmed' && v.adjustedSeverity).map(v => v.adjustedSeverity)
    const severity = (adj.length && adj.every(s => s === adj[0])) ? adj[0] : f.severity
    return { ...f, severity, status, votes: vs }
  })
}))

return {
  lensVerdicts: reviews.map(r => ({ lens: r.lens, verdict: r.verdict, rawCount: r.findings.length })),
  confirmed: verified.filter(f => f.status === 'confirmed'),
  uncertain: verified.filter(f => f.status === 'uncertain'),
  refuted: verified.filter(f => f.status === 'refuted'),
}
